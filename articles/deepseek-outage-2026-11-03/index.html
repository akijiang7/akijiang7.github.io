DeepSeek web and API partially unavailable for 1h49m on Nov 3

Key points

  • DeepSeek's official status page recorded an incident titled "DeepSeek 网页/API 部分中断（DeepSeek Web/API Partially Unavailable）" on November 3, 2026.
  • Duration: 08:58 to 10:48 UTC (16:58 to 18:48 UTC+8), 1 hour 49 minutes. Status: resolved.
  • Affected components: DeepSeek V4 Pro API Service, DeepSeek V4.1 Flash API Service, and Chat Service.
  • This was the only incident on the status page for Nov 3.

Incident log (quoted from status.deepseek.com, times UTC)

  • 08:58 Investigating: "The issue is being investigated to identify the cause." A second identical update followed at 09:00.
  • 09:06 Monitoring: "A fix has been implemented and the results are being monitored." DeepSeek posted the same update eight more times, at 09:13, 09:36, 10:04, 10:17, 10:21, 10:25 and 10:41.
  • 10:48 Resolved: "The incident has been resolved and service has been restored."

The status page gives no root cause. Earlier incidents on the page: API degraded performance (V4 Pro API) on Oct 27; a search service error on Oct 20; and a web/API partial outage on Oct 15. The page lists uptime for Aug–Nov 2026 as 99.76% for the V4 Pro API and 99.58% for the V4.1 Flash API.

What this means for US developers

The window was about 3:58 to 5:48 AM US Eastern time (EST, UTC−5) on Nov 3, so US daytime traffic was largely unaffected. Batch or overnight jobs may have failed, though. If you depend on the DeepSeek API, subscribe to the status page's RSS feed (https://status.deepseek.com/history.rss) and keep a fallback provider or retry logic for both V4 Pro and V4.1 Flash. Both were affected together.
