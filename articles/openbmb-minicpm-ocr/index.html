OpenBMB's MiniCPM-OCR: a 1.3B document parser plus a 2B model that scores whether OCR output is right

Read the full text ↓

Key points

  • OpenBMB released MiniCPM-OCR, a family of two models: MiniCPM-OCR 1.0 (1.3B), which parses Chinese and English documents and PDFs into Markdown or JSON, and MiniCPM-OCR Jev (2B), which scores how likely an OCR result is to be correct, on a scale from 0 to 1.
  • Everything is Apache 2.0: code, documentation and model weights, according to the README (license confirmed via the GitHub API).
  • It supports vLLM, SGLang, llama.cpp and Ollama from launch, ships AWQ, GPTQ and GGUF quantizations, and includes DSpark speculative-decoding heads.
  • OpenBMB reports a score of 93.68 on Real5-OmniDocBench and 54.7 on OCRBench v2, and throughput of about 1.2 pages per second. These are the vendor's own numbers.

What happened

OpenBMB, the open-source group behind the MiniCPM models, created the MiniCPM-OCR repository on October 27, 2026 and published the weights on Hugging Face. The README calls MiniCPM-OCR 1.0 the first OCR-specific model in the MiniCPM-V/o family. It covers text, tables, formulas, charts, seals and structured information extraction, and is built for difficult inputs such as scans, photographs, curved pages and re-photographed documents. The second model, Jev, is an "OCR correctness decision model": you give it an image and an OCR result, and it returns a quality score. The idea is to flag regions that need human review, and it works on output from other OCR models too.

Key details

  • Sizes: MiniCPM-OCR 1.0 has 1.3B parameters. MiniCPM-OCR Jev has 2B.
  • Benchmarks (as reported by OpenBMB): MiniCPM-OCR 1.0 scores 93.68 on Real5-OmniDocBench and 54.7 on OCRBench v2. With DSpark decoding, OpenBMB reports a 55% gain in end-to-end processing efficiency, with throughput about 1.49× PaddleOCR-VL-1.6 and 3.62× MinerU2.5 Pro. Jev reports an AUROC (×100) of 93.6 on JevOCRBench, against 90.1 for JEV-35B-A3B. Across parsing output from MiniCPM-OCR 1.0, GLM-OCR, PaddleOCR-VL-1.6 and Xiaomi-OCR-0, its AUROC ranges from 91.9 to 93.4.
  • How to run: use vLLM, SGLang, llama.cpp or Ollama. There is a pip SDK (minicpm-ocr), a hosted Free API (platform.modelbest.ai), and SKILL.md files that a coding agent can follow to set things up. Fine-tuning is supported through LLaMA-Factory and Swift.
  • Weights: BF16, GGUF, AWQ and GPTQ for both models, and DSpark heads (BF16, GGUF) for OCR 1.0.
  • License: Apache 2.0 for code, documentation and weights.
  • Advice from the README: for Jev, set the review threshold only after testing it on a small batch of real documents.

MiniCPM-OCR is a family of models for efficient document parsing and text recognition. MiniCPM-OCR 1.0 parses Chinese and English documents and PDFs, balancing quality and efficiency across challenging inputs such as scans, photographs, curved pages, and recaptured documents. MiniCPM-OCR Jev evaluates OCR results at the region level, distinguishing problematic regions from reliable ones. It works with different parsing models to help users locate content that needs review.

MiniCPM-OCR 1.0

MiniCPM-OCR 1.0 (1.3B) is the first OCR-specific model in the MiniCPM-V/o family. It focuses on text-centric document understanding, covering text, tables, formulas, charts, seals, and structured information extraction. Its key features include:

  • 🏆 SOTA document parsing: MiniCPM-OCR 1.0 achieves a SOTA score of 93.68 on Real5-OmniDocBench, a benchmark for real-world document parsing, and demonstrates leading parsing capabilities on OmniDocBench v1.6, Wild-OmniDocBench, and olmOCR-Bench. It supports Chinese and English documents and PDFs, handling both standard documents and challenging capture conditions, including scans, curved pages, photographs, skewed pages, and recaptured documents.
  • ⚡ Efficient inference. With DSpark decoding acceleration (DSpark-BF16, DSpark-GGUF), MiniCPM-OCR 1.0 improves end-to-end processing efficiency by 55%. Its throughput is approximately 1.49× that of PaddleOCR-VL-1.6 and 3.62× that of MinerU2.5 Pro, reducing the time needed for large-scale document parsing.
  • 🔍 General recognition and information extraction: MiniCPM-OCR 1.0 achieves a SOTA score of 54.7 on OCRBench v2, demonstrating strong general OCR capabilities. It also supports key information extraction (KIE), extracting relevant document content for downstream information management and automated processing.
  • 🛠️ Easy deployment and development: MiniCPM-OCR 1.0 supports vLLM, SGLang, llama.cpp, and Ollama from day one, with multiple chip platforms and quantized versions available at release. It supports further fine-tuning and provides a pip SDK and a full-featured API for application integration and customization. You can also get started quickly with SKILL.md. Explore parsing results with the online Demo (CN / Global).

MiniCPM-OCR Jev

MiniCPM-OCR Jev is an OCR correctness decision model for text, formulas, and tables. Given an image and its corresponding OCR result, it returns a quality score from 0 to 1 to help select reliable results and locate content that needs review.

  • 🛡️ Strong performance in a small model: With only 2B parameters, MiniCPM-OCR Jev achieves an AUROC (×100) of 93.6 on JevOCRBench, outperforming JEV-35B-A3B (90.1) and approaching Qwen3.5-397B-A17B (93.8).
  • 🧩 Consistent generalization: Across parsing results from MiniCPM-OCR 1.0, GLM-OCR, PaddleOCR-VL-1.6, and Xiaomi-OCR-0, its AUROC (×100) ranges from 91.9 to 93.4.

What this means for US developers

A 1.3B Apache-licensed document parser that runs on Ollama or llama.cpp is cheap enough to run on your own machines for ingestion pipelines. That matters if documents can't leave your network. Jev is the more unusual piece. Most OCR stacks tell you what the text says, not how confident you should be in it. A separate scorer that works on other models' output lets you send only low-confidence regions to human review or a bigger model, which is often where most of the cost goes. The benchmark and throughput numbers are OpenBMB's own, so test on your own documents. The README also says the strongest coverage is Chinese and English documents.
