Kimi K3.1 Pro weights are now public on Hugging Face: 2.8T-parameter MoE under a modified-MIT license

Read the full text ↓

Key points

  • License, commercial use: a custom "Kimi K3.1-Pro License". It is MIT-style and allows commercial use, with two extra conditions. Companies that run a Model-as-a-Service business (offering inference or fine-tuning APIs to third parties) and whose total revenue, together with affiliates, exceeds US$20M in any 12 consecutive months must sign a separate agreement with Moonshot before commercial use. Embedding the model in your own product features, or simply forwarding requests, is not MaaS. Products with more than 100M monthly active users or more than US$20M monthly revenue must display "Kimi K3.1-Pro" prominently.
  • The weights are public on Hugging Face as of November 5, 2026 (UTC+8), and anyone can download them without applying. The repository creation date Hugging Face shows (Nov 2) is not the public release date.
  • Moonshot AI's Kimi K3.1 Pro weights are now public on Hugging Face at moonshotai/Kimi-K3.1-Pro. The repository is public and not gated.
  • Moonshot's official X account announced the weights release on November 4, 2026 (16:00 UTC; 00:00 on Nov 5 in UTC+8): "Releasing the model weights of Kimi K3.1 Pro". The model itself was announced on October 23, 2026 (UTC), when Moonshot's tech blog said "Full model weights will be released by Nov 4, 2026."
  • Per the model card: a Mixture-of-Experts model with 2.8T total / 104B activated parameters, a 1,048,576-token context window, text and image input (MoonViT-V2 vision encoder, 401M parameters), and MXFP4 weights / MXFP8 activations from quantization-aware training.
  • Moonshot recommends vLLM, SGLang or TokenSpeed for inference. The hosted API model ID is kimi-k3.1-pro, with OpenAI- and Anthropic-compatible endpoints.

What's in the release

The repository contains 96 safetensors shards (about 1.56 TB of storage, according to the Hugging Face API), custom modeling and processor code (trust_remote_code), a tiktoken tokenizer and the LICENSE file. Moonshot describes the model as post-trained from Kimi K3 "with large-scale joint reinforcement learning across hundreds of downstream domains". Compared with K3, it replaces the full-attention Gated MLA layers with Gated DeepSeek Sparse Attention layers (69 KDA + 24 Gated DSA attention layers).

All benchmark numbers below come from Moonshot's own model card and are partly from internal benchmarks; we have not reproduced them. Moonshot's tech blog also says that for the open-weight release it "identified and removed cyber-related data" from mid-training and RL. It reports an internal xdev-bench-hard pass@3 of 81.0% for the released model versus 90.5% for a checkpoint trained without those measures.

The model card reports multi-turn usage requirements: the full assistant message, including reasoning_content and tool_calls, must be passed back unchanged. reasoning_effort accepts low, high or max (default max).

1. Model Introduction

Kimi K3.1 Pro is an open-weight, natively multimodal agentic model, and our most capable 3T-class model to date. Post-trained from Kimi K3 with large-scale joint reinforcement learning across hundreds of downstream domains, it is the first model in the K3.1 series. With a 1-million-token context window, Kimi K3.1 Pro delivers substantial improvements in coding, 3D creation, financial research, factual accuracy, and other agentic capabilities.

All remaining scores are from the Terminal-Bench-Science leaderboard.
  3. SWE-Marathon v1.1. Kimi K3.1 Pro and DeepSeek-V4.1-Flash-1017 are evaluated with Claude Code. Other scores are from the official leaderboard.
  4. ProgramBench. The table reports binary scores: a task receives 1 if its ProgramBench score is at least 95%, and 0 otherwise. K3.1 Pro is evaluated with Claude Code. DeepSeek and GLM scores are taken from the DeepSeek release blog; remaining scores are from Vals AI.
  5. DeepSWE v1.1. K3.1 Pro is evaluated with Claude Code. Other scores come from the respective technical reports for GPT-6 Astra, Claude Opus 5.5, Claude Fable 5.1, DeepSeek-V4.1-Flash-1017, and GLM-5.3.
  6. PostTrainBench. K3.1 Pro and DeepSeek-V4.1-Flash-1017 are evaluated internally on v1.2 with Claude Code and H20 GPUs rather than H100 GPUs. For stable evaluation, all judge models use DeepSeek-V4.1-Flash-1017 at maximum effort, which best matched the official GPT-5.6-Terra (xhigh) judge in testing. Other scores are from the official leaderboard.
  7. Kimi Code Bench 2.0 and Kimi Code Bench 3.0 Long-horizon. These are internal benchmarks. K3.1 Pro is evaluated with Claude Code; all other models use their maximum-effort setting. Proprietary-model testing may involve fallback behavior.
  8. BenchCAD. Open models are evaluated on 1,000-case subsets randomly sampled from the 17,900-case Vision2Code dataset at maximum reasoning effort.   2. Agents' Last Exam. Uses the official v1.1 release, comprising 122 tasks, including 86 CLI tasks. Runs that bypass stated requirements receive zero. DeepSeek and Kimi are evaluated with Claude Code and Kimi Code, respectively; other results are from the official benchmark website.

  4. Frontier Finance. Evaluated with the official Finance Agent v2 harness.
  5. HANDBOOK.md. Evaluated with the official OpenHands-based harness, using tasks from the benchmark's early open-source v1 release.

  7. OSWorld V2.1. Kimi models use the Kimi Agent harness in the official OSWorld v2 repository. GPT-6 Astra's score is taken from Muse Wonder's technical report.

Both evaluate python-pptx, pptxjs, and Kimi's in-house DSL in a harness with integrated search and image generation. The automated grader is calibrated on more than 10,000 human judgments.
  9. BrowseComp. Uses context compaction triggered at 200K tokens and a 500-step maximum. If the limit is reached, the agent is forced to answer before judging. All runs use temperature = 1.0 and top-p = 1.0.
  10. GDPval-AA v2.1, AA-Briefcase v1.1, and AutomationBench-AA. Scores are cited from Artificial Analysis. APEX-Agents. Scores are cited from the official leaderboard.

For GDP.pdf w/ python, each original PDF is sent to a sandbox for IPython processing. Responses are graded against each rubric criterion using Gemini-3.5-Flash at medium reasoning effort and the official judging prompt. The reported score is the task-macro mean rubric pass rate.

Reasoning, knowledge, and multimodal benchmarks

  1. GDP.pdf. Each PDF is provided as page images resized to a longest edge of 1,152 pixels, interleaved with Docling-extracted text in page order. Responses are graded against each rubric criterion using Gemini-3.5-Flash Medium and the official judging prompt. The table reports the strict pass rate among fully scored responses.   2. HLE-Full and HLE-Diamond. The full evaluation sets contain 2,500 and 1,000 questions, respectively. For scores marked *, accuracy is reported on the text-only subset.
  3. Run counts. GDP.pdf, ZeroBench, and ChartoGraphy are averaged over five runs; other multimodal benchmarks are averaged over four.
  4. MMMU-Pro. Evaluated using the official protocol, preserving the original input order and prepending images to the text input.
  5. PerceptionBench. An in-house benchmark focused on atomic visual perception capabilities.
  6. Kimi Hallucination Benchmark. Evaluates factual accuracy on an internal set of challenging, de-identified prompts drawn from practical work tasks. The table reports claim-level hallucination rates assessed by fact-checking agents.

Cybersecurity benchmarks

  1. ExploitBench. K3.1 Pro is evaluated with the official harness under a 300-turn budget. The table reports the pass@5 maximum-capability score: for each environment, the best of five seeds is scored by capability flags reached out of 16; arbitrary code execution counts as all 16 capabilities. Comparison scores are from OpenAI, Anthropic, and GLM-5.3.
  2. ExploitGym. K3.1 Pro is evaluated with Kimi Code under a six-hour wall-clock budget per task. GPT-6 Astra, Claude, and GLM comparison scores are taken from their respective official reports, with Claude results using the same six-hour budget.
  3. xdev-bench-hard. K3.1 Pro is evaluated with Kimi Code; GLM-5.3 and DeepSeek-V4.1-Flash-1017 use Claude Code. The internal benchmark contains expert-curated, source-code-based vulnerability discovery and exploitation tasks. The final model is evaluated at pass@3 over a random subset of runs, without hard timeouts or output-token limits.

5. Model Usage

The thinking effort of Kimi K3.1 Pro is configured with the top-level reasoning_effort request field, which supports "low", "high", and "max" (default "max").

For multi-turn conversations and tool calls, Kimi K3.1 Pro requires the complete assistant message returned by the API to be passed back to messages as-is — including reasoning_content and tool_calls, not just content:

import openai

def chat_with_preserved_thinking(client: openai.OpenAI, model_name: str):
    messages = [
        {
            "role": "user",
            "content": "Tell me three random numbers."
        },
        {
            "role": "assistant",
            "reasoning_content": "I'll start by listing five numbers: 473, 921, 235, 215, 222, and I'll tell you the first three.",
            "content": "473, 921, 235"
        },
        {
            "role": "user",
            "content": "What are the other two numbers you have in mind?"
        }
    ]

    response = client.chat.completions.create(
        model=model_name,
        messages=messages,
        stream=False,
        max_tokens=4096,
        reasoning_effort="max",
    )
    # the assistant should mention 215 and 222 that appear in the prior reasoning content
    print(f"response: {response.choices[0].message.reasoning}")
    return response.choices[0].message.content

For full guides and examples (vision input, structured output, partial mode, tool choice, dynamic tool loading, context caching), see the Kimi K3.1 Pro Quickstart and Thinking Effort.

What this means for US developers

  • Commercial use is allowed without a fee or sign-up, unless you run a MaaS business above the revenue threshold. If you embed the model inside your own product features, or run it internally, the MaaS clause does not apply. The license explicitly excludes "end-user products with model capabilities solely embedded within specific features or harnesses" and internal use.
  • If you resell raw inference or fine-tuning (an API where customers control inputs, parameters or training data), check your group's revenue. Above US$20M over any 12 consecutive months, you need a separate agreement with Moonshot before commercial use. Revenue is counted across you and your affiliates, not only the AI business.
  • Plan attribution for scale. Consumer products above 100M MAU or US$20M monthly revenue must display "Kimi K3.1-Pro" prominently in the UI.
  • Hardware: at about 1.56 TB of weights, self-hosting needs a multi-GPU cluster. Most teams will use the Kimi API or a hosted provider. Use through Moonshot's official products or "certified inference partners" is exempt from the MaaS and attribution conditions.
  • Weigh export-control, data-governance and procurement policies (some US agencies restrict PRC-developed models) before deployment. The license itself contains no field-of-use restrictions beyond compliance with applicable law.
