MiniMax open-sources mcode-stack: the skills and checklists its coding-agent team actually uses

Read the full text ↓

Key points

  • MiniMax published mcode-stack, a collection of SKILL.md skills, checklists and workflows that the MiniMax Code team says it uses every day to build MiniMax Code.
  • The skills install as plugins in Claude Code, Codex and MiniMax Code, and most work in any agent that supports the common SKILL.md format.
  • Topics include deciding when to use subagents, auditing tool and context cost, keeping long sessions sharp, waiting on long commands, independent code review and running small harness experiments.
  • The license is MIT (confirmed via the GitHub API), except the engineering-* skills, which are adapted from Google Engineering Practices and stay under CC-BY 3.0.

What happened

MiniMax created the repository on October 28, 2026. The README describes it as "not a prompt collection or a list of 'best practices'", but what the team actually uses: how to keep AI-written code to a high standard, when to hand work to a subagent, how long to wait on a long command, and what goes into context on every turn. Each "stack" belongs to one team member. stacks/ronny, from the MiniMax Code R&D lead, is the first and most complete. stacks/jiachen adds skills for getting out of manual agent loops and for turning notes into Xiaohongshu posts and short videos. The skills go with a series of articles called MCode Engineering Notes.

Key details

  • Install: in Claude Code, run claude plugin install ronny --marketplace MiniMax-AI/mcode-stack. In Codex, run codex plugin marketplace add MiniMax-AI/mcode-stack, then codex plugin add ronny@mcode-stack. In MiniMax Code, copy a skill folder into ~/.agents/skills/, or add the marketplace in the desktop app.
  • Skills in stacks/ronny: subagent-split-check, engineering-small-prs, tool-budget-audit, context-tax-audit, long-session-check, handoff-doc, long-command-check (a ten-point audit), independent-review, harness-experiment, trajectory-review and others.
  • Not included: MiniMax Code's source code, which lives in MiniMax-AI/minimax-code.
  • Contributions: pull requests are accepted only from repository collaborators for now. Everyone else should open an issue.
  • License: MIT, except where a stack's NOTICE.md says otherwise. The adapted Google material stays under CC-BY 3.0.

The workflows and skills the MiniMax Code team uses to build MiniMax Code. Open source, install and use.

This is not a prompt collection or a list of "best practices". It is what people on the team actually use every day: how to keep AI-written code at a high bar, how to decide whether a task should go to a subagent, how long to wait on a long command, how to keep long sessions from going dull, and what goes into context on every turn. Each piece is a SKILL.md skill or checklist that installs straight into MiniMax Code.

Quick start

Claude Code, one command. The command adds this marketplace and installs a whole stack. In a shell:

claude plugin install ronny --marketplace MiniMax-AI/mcode-stack

Inside a Claude Code session:

/plugin install ronny --marketplace MiniMax-AI/mcode-stack

Use jiachen in place of ronny for that stack. From a clone of this repository, scripts/install.sh installs ronny (scripts/install.sh jiachen for that stack) with claude or codex when either is on PATH, and otherwise copies that stack's skills into ~/.agents/skills/.

Older Claude Code can add the marketplace first, then install:

/plugin marketplace add MiniMax-AI/mcode-stack
/plugin install ronny@mcode-stack

Codex. Add the marketplace, then install from the Plugins Directory or the CLI:

codex plugin marketplace add MiniMax-AI/mcode-stack
codex plugin add ronny@mcode-stack

Substitute jiachen the same way. To take a single skill instead of the plugin, copy that skill's folder into ~/.agents/skills/. Codex and MiniMax Code both scan that directory; the copy steps are below.

One skill, for all your projects:

git clone https://github.com/MiniMax-AI/mcode-stack.git ~/mcode-stack
mkdir -p ~/.agents/skills
cp -R ~/mcode-stack/stacks/ronny/skills/long-command-check ~/.agents/skills/

Open a new session and type /skills in MiniMax Code to see it. Run it with /long-command-check, or let the agent load it from its description.

The whole stack, as a plugin:

mcode plugin marketplace list    # shows your local plugin directory

Copy the whole stacks/ronny directory into that directory, then open /plugins in MiniMax Code and press Ctrl+R to refresh. A local plugin is installed as soon as it is in that directory; press Space in the panel to enable or disable it.

Every stack, from the MiniMax Code marketplace:

This repository is also a plugin marketplace, so you can install a stack without copying files and pick up updates later. In MiniMax Code desktop, open Plugins, choose Add marketplace and enter MiniMax-AI/mcode-stack; each stack then shows up as one plugin you can install, update or uninstall. Adding marketplaces is rolling out gradually, so your version may not have it yet.

More install options

MiniMax Code discovers skills in these directories (one subdirectory per skill, containing SKILL.md):

  • For the current project only: .minimax/skills/, .claude/skills/ or

.agents/skills/ in the project

  • For all projects: ~/.agents/skills/ (~/.claude/skills/ and

~/.codex/skills/ are read too)

mcode plugin add installs from the official catalog only; it does not take a GitHub URL or a local path.

The skills use the common SKILL.md format, so most of them also work in other agents that support skills.

How it works

AI writes code faster every month. What separates results now is the layer of engineering habits around the agent: when to make it stop and check its own work, who reviews, where state lives, what counts as a real experiment. Those habits are hard to follow from an article, so we turned them into skills and checklists. They pair with our MCode Engineering Notes column: the article explains the idea, this repository makes it runnable.

We also believe harness engineering is a craft that moves forward by experiment. Everything here will keep changing as we learn. Take it and change it. To suggest a change here, open an issue; see Contributing.

Contributing

Issues and discussion are welcome. For now, pull requests for code, documentation, and stacks are accepted only from repository collaborators. If you are not a collaborator, open an issue to discuss first.

We still want to hear how you work with MiniMax Code, or any other agent, day to day. Share that in an issue. Collaborators adding a stack:

  1. Copy templates/stack-template/ to community/<your-id>/.
  2. Write a WORKFLOW.md: how you use the agent every day, what you hand to it and what you keep an eye on yourself.
  3. Add at least one skill or checklist you really use.
  4. Run node scripts/check.mjs, then open a PR with the output and a short record of real usage.

Details in CONTRIBUTING.md. Using something from here in your own agent? Tell us with an I use this issue.

Relationship to MiniMax Code

MiniMax Code itself lives in MiniMax-AI/minimax-code. This repository only holds workflows and skills, no MiniMax Code source code.

What this means for US developers

This repo isn't tied to MiniMax's models, so you can use it right away. The skills install directly into Claude Code and Codex, and they cover problems every team running coding agents has: context bloat from too many tools, prompt-cache misses, long sessions that drift, and agents grading their own work. independent-review, which reviews a diff from a clean context with only the diff, the requirement and the test results, is a pattern worth copying whatever agent you use. Check licensing before you redistribute. The repo is MIT, but the engineering-* skills are CC-BY 3.0 and require attribution.
