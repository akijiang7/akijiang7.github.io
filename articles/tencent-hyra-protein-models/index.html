Tencent Hunyuan's Hyra 2.0 research agent releases two protein models: HyInv (1.96M-param inverse folding) and HyPLM-Flash (650M-param protein LM)

Read the full text ↓

Key points

  • On November 2, 2026, Tencent Hunyuan added two protein models to its Hyra-results repository on GitHub. Hyra is short for "Hunyuan Research Agent". According to the READMEs, both models were trained by the research agent Hyra 2.0, and both ship with weights, inference code and a technical report.
  • HyInv is a 1.96-million-parameter graph neural network for protein inverse folding: it takes a backbone structure and designs a sequence. It follows ProteinMPNN's message-passing design and was trained with structure-reward reinforcement learning. The 7.8 MB weights ship in the repository, and it runs on CPU or GPU.
  • HyPLM-Flash is a 650-million-parameter masked protein language model with an INT8 GPU inference engine. Its README reports a ProteinGym zero-shot Spearman correlation of 0.409, which it calls statistically tied with ESM-2 650M, ESM C 600M and E1-600M. It also reports about 130,000 residues per second on one H20 GPU. The 2.6 GB of weights are published as a GitHub Release.
  • Licenses: each model package carries its own MIT license file (HyInv's copyright line is ProteinMPNN's, "Copyright (c) 2022 Justas Dauparas"). The repository-wide LICENSE says Tencent-authored materials are Apache-2.0 "unless otherwise specified". GitHub's API reports the repository license as "Other" (NOASSERTION) because of the custom header.
  • Neither model has a Hugging Face model card. An HF search for "hyinv", "hyplm" and "hyra" under Tencent returned no repositories.

What happened

Hyra-results is the companion repository for Tencent Hunyuan's Hyra launch post at hy.tencent.com/research/hyra. It collects solutions the agent produced across mathematics, science and engineering problems. Its News section for 2026-11-02 announces "two protein models released with weights and code", published under AI4Science/hyinv/ and AI4Science/hyplm_flash/. The same day the repository also added HyFF, a set of machine-learning force fields, and two mathematics results. This article covers the protein models only.

The HyPLM-Flash weights were published as GitHub Release hyplm-flash-weights on Nov 2, 2026 at 16:50 (UTC+8). The release contains two shards, model.safetensors.part0 and part1.

HyInv (AI4Science/hyinv/README.md)

HyInv is a 1.96-million-parameter graph neural network for protein inverse folding (backbone → sequence), trained by our research agent Hyra 2.0. It follows the message-passing design of ProteinMPNN with a 4-layer encoder and a 3-layer decoder, sees only the N, Cα, C and O backbone atoms, and runs on both CPU and GPU. The released weights are the structure-reward reinforcement-learning version; deployment samples in 16 rounds — encode once, 8 rounds of blind drafting (temperature 0.6), then 8 rounds of rewriting by fixed groups (temperature 0.34).

Technical report: HyInv_Technical_Report.pdf

Installation

Python 3.10+ and PyTorch; the only other dependencies are safetensors and numpy. Accelerated inference additionally needs triton.

pip install -e .
pip install -e '.[fast]'   # optional: accelerated inference on CUDA GPUs
Usage
python -m hyinv design --pdb structure.pdb --n 128 --seed 0 --out designs.fasta
python -m hyinv design --pdb structure.pdb --chain A --fixed 12-20,45 --n 16   # keep residues 12-20 and 45

Options: --draft-temperature 0.6, --rewrite-temperature 0.34, --device cpu|cuda, --fast off|exact|bf16 (see Accelerated inference), --weights DIR. For multi-chain structures pass --chain AB, or omit --chain to read all chains; chains are separated by / in the output, and fixed positions must be qualified with a chain name (e.g. A12-20,B7).

from hyinv import HyInv, read_pdb, design

model = HyInv.from_pretrained(device="cuda")          # reads the bundled weights/ by default
structure = read_pdb("structure.pdb", chains="A")
sequences = design(model, structure, n=8, seed=0, fixed="12-20,45")   # list[str]
Accelerated inference

On a CUDA GPU the decoder can run as fused Triton kernels, with the whole 16-round sampler captured in a single CUDA graph. This needs a CUDA build of PyTorch and triton (pip install -e '.[fast]'; verified with triton 3.3.1 on an H20). --fast has three settings and defaults to off:

  • off: reference implementation (FP32, CPU or GPU).
  • exact: FP32-level acceleration (TF32x3 accumulation, erf GELU). With the same arguments (pdb, seed, n, batch size, fixed positions) the sequences are almost always identical to off: batch splitting, seeds (batch k uses seed+k) and position groups are exactly the same. TF32x3 does not accumulate in bitwise FP32 order, so when the sampling probabilities are nearly tied an occasional position can flip; across about 8,000 independently checked sequences of varying length (including missing atoms, two chains and fixed positions), only one differed at one position.
  • bf16: BF16 operands with FP32 accumulation and tanh GELU, the fastest setting. This is a numerically-different path: sequences with the same seed are not identical to off (they are another sample from the same distribution; see the technical report for the S@D gap and speed measurements on the development set). It is reproducible with itself under the same arguments, and fixed positions are kept.
python -m hyinv design --pdb structure.pdb --n 128 --fast bf16 --out designs.fasta
sequences = design(model, structure, n=128, seed=0, fast="bf16")   # or "exact"; model must be on CUDA

Speed (128 designs, max candidate batch 32, one H20, excluding compilation and graph capture, median): bf16 about 25 / 54 ms for 148 / 402 residues (24.7 / 50.6 ms in the technical report); exact about 119 / 281 ms (the report's exact path uses another set of kernels: 130 / 303 ms); the reference implementation takes 999 / 2,633 ms under the same conditions (bf16 and reference numbers are from the technical report). Notes:

  • The first call compiles the Triton kernels (about 25 s for exact and 14 s for bf16 with a cold cache, then cached on disk) and captures a CUDA graph per (backbone length, batch size) (about 0.1–0.2 s for a new shape); later calls with the same shape only replay. A different batch size or a smaller final batch captures once more, with at most 4 lengths cached.
  • Captured graphs occupy GPU memory, and the model weights must not change after the first call.
  • Verified on a Hopper-class GPU (H20, sm_90); the kernels should compile on other architectures but have not been verified.
  • Speed is sensitive to the number of CPU threads (we suggest torch.set_num_threads(2)).
Notes
  • Input: ATOM records of the first model in the PDB file (MSE is treated as MET); each residue takes one slot, and residues with missing backbone atoms keep their slot and are designed; residues are numbered 0..n-1 within each chain, without filling gaps in the PDB numbering. Convert mmCIF to PDB first.
  • Fixed positions are given by PDB residue number; they are visible as the native residue from the first round on and are kept unchanged in the output.
  • Reproducibility: outputs are identical for the same seed, batch size (default 64, automatically tightened by length), device type and PyTorch version; each batch has its own random stream (batch k uses seed+k), so changing the batch size changes the result. The CPU and GPU random streams differ, so their sequences are not identical.
  • The default path is the reference implementation (FP32); see Accelerated inference above.
Layout
  • hyinv/: model (model.py), sampler (sampler.py), PDB reader (pdb.py), command line (__main__.py), accelerated inference (fast.py, _kernels.py; requires triton)
  • weights/: model.safetensors (FP32, 7.8 MB) and config.json
  • HyInv_Technical_Report.pdf: technical report

HyPLM-Flash (AI4Science/hyplm_flash/README.md)

HyPLM-Flash is an efficient, open protein language model: a 650-million-parameter masked language model trained by our research agent Hyra 2.0 on 0.73 times the data of ESM-2 650M and a fifth to an eighth of the data of E1-600M and ESM C 600M. In a matched evaluation of 28 public checkpoints on 32 tasks it reaches a ProteinGym zero-shot Spearman correlation of 0.409, statistically tied with ESM-2 650M, ESM C 600M and E1-600M, gives the best long-range contact precision of all evaluated models, and its inference engine embeds about 130,000 residues per second on a single H20, 1.9 to 2.7 times faster than other 600M-class encoders.

Technical report: HyPLM_Technical_Report.pdf

Installation

Needs a CUDA GPU (Hopper GPUs such as the H20 or H100 recommended) and Python 3.10+. The 2.6 GB of FP32 weights are released as two shards in this repository's GitHub Releases; download, merge and verify them with:

bash weights/download.sh     # needs curl; set GITHUB_TOKEN only if you hit API rate limits
pip install -e .             # torch, safetensors, triton, flash-attn

FlashAttention-3 (flash_attn_interface) is used automatically when installed, otherwise FlashAttention-2.

Usage
from hyplm import HyPLMEncoder

encoder = HyPLMEncoder.from_pretrained("weights")       # INT8 by default
sequences = ["MKTAYIAKQRQISFVKSHFSRQ", "ACDEFGHIKLMNPQRSTVWY"]

residue = encoder.encode(sequences)                     # list of [L, 1280]
pooled = encoder.encode(sequences, pooling="mean")      # list of [1280]
layer16 = encoder.encode(sequences, layer=16)           # output of block 16

Returns a list of CPU FP32 tensors in input order, without the leading and trailing special tokens. A single sequence may be up to 8,190 residues; input is upper-cased, whitespace is removed and J is converted to X, while invalid characters raise an error. Proteins are automatically packed into padding-free batches with batch_tokens (default 32768) tokens per batch.

Masked-language-model logits, e.g. for zero-shot mutation scoring:

sequence = "MKTAYIAKQRQISFVKSHFSRQ"
logits = encoder.logits(sequence, masks=[2])[0]         # [L, 33]; residue 3 is replaced by <mask> first
log_probs = logits[2].log_softmax(-1)
tokens = encoder.tokenizer.tokens                       # vocabulary order
score = log_probs[tokens.index("V")] - log_probs[tokens.index("T")]   # masked-marginal score of T3V
Precision
ModeH20 throughput (residues/s)Recommended for
precision="int8" (default)about 130,000representation extraction, zero-shot scoring, structure and function prediction
precision="bf16"about 90,000training supervised regressors on near-identical variants (e.g. AAV and GB1 in FLIP)

Under INT8, zero-shot, structure, function-annotation and likelihood metrics are within 0.01 of BF16. Representations of variants of the same protein differ by only about 1%, so BF16 is recommended when training regressors on such data.

Command line and multiple GPUs
python -m hyplm MKTAYIAKQRQISFVKSHFSRQ --pooling mean --output embeddings.pt
from hyplm.engine import encode_multi_gpu

if __name__ == "__main__":  # one worker process per GPU
    vectors = encode_multi_gpu(sequences, checkpoint="weights", pooling="mean")

For low-latency inference on a single protein, use hyplm.engine.graphs.GraphRunner (CUDA graphs).

Layout
  • hyplm/: inference interface and engine (padding-free packing, fused Triton kernels, INT8 matrix multiplication)
  • weights/: model config and download.sh; the FP32 weights (safetensors, 2.61 GB) are fetched from the GitHub Release
  • HyPLM_Technical_Report.pdf: technical report

What this means for US developers

Both models are small, permissively licensed and easy to try. HyInv is a 7.8 MB, CPU-capable drop-in for ProteinMPNN-style sequence design, installed with pip install -e ., and it has a Python API. HyPLM-Flash targets teams that embed large protein sets with ESM-2-class encoders: if the reported throughput holds on your hardware, it could cut embedding costs. It does need a Hopper-class GPU and FlashAttention, and the published speed numbers are all on Chinese-market H20 cards, so benchmark on your own H100s or other GPUs before switching. One license detail: the MIT terms are in each package's own LICENSE file, while the repository-level LICENSE is a Tencent Apache-2.0 header with a "unless otherwise specified" carve-out. Cite the package licenses if you redistribute. All benchmark claims come from Tencent's own technical reports and have not been independently reproduced.
